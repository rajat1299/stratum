# SAML SSO Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a conservative provider-free SAML SSO foundation for tenant-scoped hosted auth while preserving OIDC, refresh-token, local user, agent bearer, workspace bearer, and hosted `Stratum-Session` behavior.

**Architecture:** Reuse the Slice 16a hosted auth session and refresh-token machinery. SAML login gets its own provider-free verifier/parser seam, typed metadata/assertion validation, assertion replay tracking, and redacted audit lifecycle events; successful SAML verification produces the same `HostedSessionIdentity` and token response shape as OIDC. SAML remains disabled by default behind explicit runtime gates, and durable schema changes are additive through migration 0017.

**Tech Stack:** Rust 2024, Axum, Tokio, serde, uuid, SHA-256 hashing, existing `auth::hosted`, `Session`, `ServerState`, tenant repo resolver, audit store, Postgres migration runner, and provider-free tests.

## Current State

- `src/auth/hosted.rs` owns provider-free hosted access sessions, refresh-token families, token hashing, default-disabled OIDC verification, and redacted debug output.
- `src/server/routes_auth.rs` exposes `POST /auth/oidc/login`, `POST /auth/refresh`, and `POST /auth/refresh/revoke`. OIDC success issues the same hosted access and refresh tokens that SAML should reuse.
- `src/server/middleware.rs` authenticates hosted sessions only through `Authorization: Stratum-Session <access-token>`. Existing `Authorization: Bearer <token>` agent/workspace behavior and `Authorization: User <username>` local behavior are unchanged.
- `src/server/repo_context.rs` resolves tenant before repo and can bind hosted session org/repo identity to route context while rejecting header mismatches.
- `src/audit.rs` has OIDC login and refresh-token lifecycle actions and auth resource kinds.
- `src/backend/runtime.rs` defaults hosted auth to disabled and currently recognizes only `STRATUM_HOSTED_AUTH_PROVIDER=oidc-dev` as a provider-free dev mode.
- Postgres migration 0016 added OIDC provider, external identity, refresh-token family, and refresh-token tables. There is no SAML provider table, metadata model, assertion replay table, route, verifier, runtime mode, or group mapping model.

## Boundaries

- Do not implement SCIM, hosted admin UI, tenant/user provisioning UI, production IdP metadata URL fetching, production XML signature validation against live IdP metadata, production KMS/secrets-manager, MFA/passkeys, Redis, SDK releases, or crates.io publishing.
- Normal tests must not call a real IdP, fetch metadata URLs, load certificates from the network, require Postgres/R2/live credentials, or depend on durable-cloud env.
- Public errors, `Debug`, logs, audit details, and docs examples must not expose raw SAML assertions/XML, NameID values, certificate bodies, private keys, provider error bodies, request bodies, access tokens, refresh tokens, token hashes, DB URLs, or sensitive provider URLs.
- Existing OIDC, refresh, local user, agent bearer, workspace bearer, and hosted `Stratum-Session` behavior must remain unchanged unless a test proves an explicit planned regression fix is needed.
- SAML must fail closed when disabled, partially configured, malformed, expired/not-yet-valid, replayed, group-mismatched, tenant-mismatched, audience/ACS/entity-mismatched, or bound to an unknown principal/external identity.

## Design

### SAML Provider Model

Add a typed provider-free SAML model under `src/auth/hosted.rs`:

- `HostedSamlVerificationRequest<'a>` with `provider`, `saml_response`, optional `relay_state`, requested `org_id`, and requested `repo_id`. `Debug` must redact `saml_response` and `relay_state`.
- `SamlProviderMetadata` with bounded `provider_key`, `org_id`, `repo_id`, IdP entity ID, SP entity ID, ACS URL, audience, binding, signing certificate reference/hash, group attribute name, and optional required external group.
- `SamlBinding` supporting only HTTP-POST in this foundation.
- `VerifiedHostedSamlClaims` with `org_id`, `repo_id`, `uid`, `username`, `gid`, mapped `groups`, bounded `external_identity_id`, assertion ID hash, `not_before_unix`, `expires_at_unix`, audience, ACS URL, issuer/entity ID, and provider key.
- `HostedSamlVerificationError` with redacted variants for disabled provider, invalid metadata, invalid assertion, expired/not-yet-valid assertion, replay detected, group mapping mismatch, tenant mismatch, and provider denial.

Validation should be typed and provider-free. Tests may inject fake verifier/parser implementations with structured metadata and assertion fixtures; production default remains disabled and never parses real XML or calls network providers in this slice.

### Metadata And Assertion Validation

Add validation helpers that reject:

- Empty, malformed, non-ASCII, or oversized entity IDs, ACS URLs, audiences, provider keys, group names, and certificate references.
- Unsupported bindings. Only HTTP-POST is accepted.
- Missing or invalid signing certificate references. Store or compare hashes/references only, not raw certificate bodies.
- ACS URL or audience mismatch between provider metadata and assertion claims.
- Issuer/entity ID mismatch between IdP metadata and assertion claims.
- Expired or not-yet-valid assertions.
- Assertion ID replay while the original assertion validity window is still active.
- Unknown external identity or principal shape when represented in the fixture/store.

The provider-free foundation does not claim production XML signature validation. It creates seams and tests around the inputs that production XML/signature verification must supply later.

### Group Mapping

Represent group mapping conservatively:

- Map external SAML group names to existing local gids or durable principal group ids.
- Allow an optional required external group per provider/config fixture.
- Reject login if required group is absent or no mapped group can be produced for a tenant-scoped principal.
- Do not implement SCIM, group provisioning, invitations, or hosted admin UI.
- Store hashes or bounded names only where durable schema needs the mapping; do not store raw assertion XML or arbitrary group attribute blobs.

### Login Route

Add `POST /auth/saml/login` with JSON:

```json
{
  "provider": "provider_key",
  "saml_response": "<base64-or-fixture-token>",
  "relay_state": "<optional>",
  "org_id": "org_a",
  "repo_id": "repo_a"
}
```

The route should:

- Bound all input fields before verification.
- Call the SAML verifier seam.
- Validate requested org/repo against verified claims and `TenantRepoResolver`.
- Reject tenant/header/assertion mismatches without falling back to local/root identity.
- Record assertion replay use before issuing tokens.
- Reuse hosted `issue_access_token` and `issue_refresh_token`.
- Return the same `HostedTokenResponse` shape and `token_type: "Stratum-Session"` as OIDC.
- Emit redacted SAML login denial/success and refresh issue audit events.

### Runtime Gates

Extend hosted auth runtime config without enabling production SAML:

- `STRATUM_HOSTED_AUTH_PROVIDER=disabled` remains default.
- Add `STRATUM_HOSTED_AUTH_PROVIDER=saml-dev`.
- `saml-dev` requires `STRATUM_HOSTED_AUTH_ENABLE_DEV=1` plus SAML-specific hash/reference env vars, for example:
  - `STRATUM_SAML_PROVIDER_KEY`
  - `STRATUM_SAML_IDP_ENTITY_ID_HASH`
  - `STRATUM_SAML_SP_ENTITY_ID_HASH`
  - `STRATUM_SAML_ACS_URL_HASH`
  - `STRATUM_SAML_AUDIENCE_HASH`
  - `STRATUM_SAML_SIGNING_CERT_REF_HASH`
- Partial SAML/OIDC mixed config must fail closed with env-name-only messages before local `.vfs` files are created.
- Durable-cloud readiness checks must still run before hosted provider validation so invalid raw provider values are not echoed in durable startup errors.

### Postgres Migration

Add migration `0017_saml_sso_foundation.sql` and register it in `src/backend/postgres_migrations.rs`.

Additive tables:

- `saml_providers`: org/repo-scoped provider metadata hashes/references, binding, group attribute, optional required group hash, enabled flag, lifecycle timestamps, unique `(org_id, repo_id, provider_key)`, and shape FKs to `organizations`, `repos`, and durable principals where applicable.
- `saml_external_identities`: org/repo/provider/principal binding with `name_id_hash`, bounded username hint, lifecycle timestamps, and shape FKs to `saml_providers` and `durable_principals`.
- `saml_group_mappings`: provider-scoped external group hash/name reference, local gid, required/active flags, lifecycle timestamps.
- `saml_assertion_replay`: provider/org/repo/principal assertion ID hash, first-seen timestamp, expires-at timestamp, and uniqueness to block replay.

Do not alter or weaken OIDC/refresh-token constraints. Extend adoption verification so missing/weakened SAML tables, constraints, FKs, hash checks, indexes, or lifecycle checks fail adoption.
